# What's still open

{: .in-short }
The questions we haven't answered yet, and the things we're assuming without proof.
This is where your views would help most.

## Open questions

**Records**
- Is xAPI the right standard for recording answers, or would another one suit better?
- Who creates the ID for each session, and how do we know a session has ended?
- Do tools need a shared list of common misconceptions, so their reports can be combined?
- How should reports from different tools be weighed against each other?

**Where records live**
- Who should run the stores in the long term: us, schools, or someone else?
- Which tools may read and write which school's records?
- How long are records kept, and how is someone's data removed when they ask?

**The curriculum and materials**
- How do tools' own materials, such as their question banks, get linked to lessons?
- What happens to records when the curriculum map changes?
- How sure does a match need to be before we treat it as certain?

**Classroom context**
- How up to date does it need to be?
- How should a teacher's own scheme of work be included?

## Assumptions we're relying on

These are things we're treating as true without proof yet.
The ones most likely to be wrong, and that would matter most if they were:

- **Tools will let us see their quiz questions, or describe them for us.**
  Without this, we can't tell which lesson a tool's quiz is about.
- **All tools mean the same thing by how confident they are.**
  If one tool's "fairly sure" is another's "very sure", combining their reports gets harder.

Others we're relying on:

- Tools will share each answer a pupil gives, not just a final score.
- Every tool can use the same pupil ID the school gives.
- Tools know when a session starts and ends.
- Looking up a pupil's answers stays quick, even after a year of them.
- We can read the text in the files schools hold, including scans and slides.
- Most school materials cover one lesson.

If you know any of these to be true or false, please tell us: see [How to comment](how-to-comment.md).
