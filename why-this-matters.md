# Why this matters

{: .in-short }
Tools start from scratch with every pupil, teachers' own materials go unrecognised, and what one tool learns is lost when a pupil moves to another.
A shared way of passing this information on would fix all three.

## Tools start from scratch

When a session starts, an AI tutoring tool has no standard way to find out what the pupil has already been taught, or what they find hard.
So it either spends the first part of the session working it out, or it guesses.
A human tutor who'd been told "they covered this last week, and they mixed up these two ideas" would start in a very different place.

## Teachers' own materials aren't recognised

Teachers mostly teach with their own worksheets, slides and quizzes.
Most of these aren't labelled with which lesson they belong to, and we don't want to ask teachers to start labelling them.
So today, a tool can't easily use the materials the pupil's own teacher has chosen.

## What a tool learns gets lost

Each tool keeps what it learns about a pupil to itself.
When a school changes supplier, or a pupil uses a different tool for another subject, that knowledge doesn't go with them.

## Why a shared approach

There are already several AI tutoring tools, and thousands of schools, each organising their content and the curriculum in their own way.

If every tool had to understand every other tool's format, the number of connections would grow very fast.
Instead, each tool and school connects once, to one shared map of the curriculum, through the **integration layer**: a system that sits between schools and AI tutoring tools.
Then any tool can understand what any other tool recorded.

It also means no single company ends up holding the only detailed picture of a pupil's learning.
